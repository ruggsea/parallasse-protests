# Write a custom scraper for ONE news outlet

Outlet: {outlet} ({country}), domain {domain}, id {id}.
Goal: a Python script `scrapers/custom/{id}.py` (relative to .) that lists the article URLs the outlet published from 2026-09-25 to 2026-10-25 and writes them to `data/urls_custom/{id}.tsv`, one line `URL<TAB>YYYY-MM-DD` (the publication date as the site states it in a sitemap lastmod, archive page date or feed), no header, unique URLs. Then write the JSON file {OUT} containing {"script": "scrapers/custom/{id}.py", "notes": "what you tried, with status codes, and why the final route works"}.

FIRST ACTION, before any research: write {OUT} as a stub {"script": "scrapers/custom/{id}.py", "notes": "stub"} so a timeout cannot leave you with nothing; overwrite it with real notes at the end. Work in small steps: probe, write the script early (even a partial one), run it, improve it. Long silent thinking costs you the attempt; engines are slow and shared, so keep each step short and save the script after every improvement.

Rules
- Every HTTP request goes through `from polite_fetch import fetch` (sys.path.insert(0, "./scrapers"); `status, text, _ = fetch(url)`). It respects robots.txt, rate-limits per host and logs. Never use curl, requests or urllib to the outlet directly. If robots.txt DISALLOWS the path, that route is closed: pick another. A 403/429/WAF answer is not a robots block: try again later at a slower rate, other routes, AMP pages, the site's feeds.
- Work out the route by inspecting the site: robots.txt Sitemap lines, news sitemaps, per-day or per-month sitemaps, date archive pages (/archivio/YYYY/MM/DD ...), section pages with paging, the site search with date filters, RSS/Atom, JSON APIs the site's own pages call, AMP pages, the Wayback CDX API (web.archive.org/cdx/search/cdx?url=DOMAIN/*&from=20260925&to=20261025&output=json&collapse=urlkey; slow, retry on timeout, 1 request/s). Combine routes if one is not enough. Previous attempts (read them first): grids/recipes/out/{id}.json and grids/italy_fallback/out/{id}.json if present.
- The script must run on its own in under 20 minutes and print how many URLs it wrote per day. RUN IT YOURSELF to the end before you finish and leave data/urls_custom/{id}.tsv as its output (the check does not run it, it reads that file; it must be newer than the script; the script is run again later for the final list). The script must be a complete, valid Python file (no stray heredoc markers).
- Check that will judge you: it runs your script, then requires at least 15 distinct URLs dated on each of 2026-09-30, 2026-10-10 and 2026-10-20, all dates inside the window, no URL twice, and re-fetches 4 sample articles: each must give 1500+ characters of text and a page date within 1 day of the listed date. Test this yourself before you finish. Do not invent dates; a listed date comes from the site.
- Your LAST action must be running the script to the end. Never edit the script after its last run (108 attempts failed with 'the tsv is older than the script'). If you edit, rerun.
- Never print more than ~2000 characters of a page or listing (24 attempts overflowed the context window). Cap yourself at about 60 requests; use `head -c 2000` or slice in Python.
- If the outlet genuinely publishes fewer than 15 articles on one of the three days (check the sitemap counts first), write that in the notes with the counts instead of burning the attempt: set "low_volume": true in {OUT} (the check then accepts it if at least 10 URLs are listed and the sample articles are good). Do not use this for an outlet whose archive you simply failed to reach.
- Second way to find URLs when the outlet's own archive is closed to you (for big outlets this is the main route): (a) news sitemap or sitemap index by date (robots.txt Sitemap lines, /sitemap-YYYY-MM-DD.xml, /sitemap/YYYY/MM); (b) NOT the Common Crawl index: index.commoncrawl.org/robots.txt disallows everything except collinfo.json, so it is closed; (c) GDELT DOC API (domain filter, per day). The listed date must still come from the site or the index timestamp of the page you fetched; the scraper then only fetches the articles.
- Only write inside scrapers/custom/ and data/urls_custom/ and the {OUT} file. Never kill processes by name.
